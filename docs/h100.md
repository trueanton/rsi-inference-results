# H100 baseline qualification

These runs use Apple’s original public tasks, workload definitions and assigned hardware. Qwen3.6-27B served BF16 on one H100 at TP=1. GPT-OSS-120B served MXFP4 on two H100s at TP=2. Both passed public correctness on 20 prompts. The two run summaries report 9,752 completed timed requests and zero failures across both arms. The original verifier returned `no_patch` for each unchanged tree. There was no modified candidate to time. Each arm measured four 1,024-in/8,192-out requests per decode boot, five repetitions of 256 8,192-in/1-out requests for prefill, and 256 1,024-in/1,024-out requests per high-load profile and repetition. Qwen used one decode boot and one high-load repetition. GPT used two decode boots and two high-load repetitions. The table excludes warmups. It averages per-run statistics, dropping the lowest and highest values in the five-run prefill series. The harness separately computes the decode and prefill scores from reciprocal median latencies, and combines high-load request rates by geometric mean across the three profiles. The five rows per model are profile aggregates. For Qwen, decode and each high-load profile have one observation per arm. For repeated profiles the individual measurements in the timing archives show the observed spread.

## Interpreting the paired results

| Unchanged first arm / pristine arm | Decode | Prefill | High load | Overall |
| --- | ---: | ---: | ---: | ---: |
| Qwen3.6-27B | 0.982468× | 0.996439× | 1.001517× | 0.993442× |
| GPT-OSS-120B | 1.082275× | 1.010081× | 1.001347× | 1.030606× |

The H100 run summary records **1.082275×** for GPT decode. That score uses reciprocal median time per output token. As a separate observation, the first arm delivered 216.16 and 216.13 output tokens/s in its two decode boots. The two pristine boots delivered 199.81 and 199.41 output tokens/s, averaging 199.61. The run notes record the same devices, seed, NCCL 2.27.5, FlashAttention 3 and Triton MXFP4 for both arms, with a separate compilation cache per arm. The cause of the 8.23% score difference remains unresolved.

## Setup and evidence

Both jobs used Apptainer 1.4.5 and the original workload definitions. Qwen used three CUDA 12 package overrides to satisfy the installed Torch wheel. GPT matched all 191 original pins and used a checksum-verified offline Harmony vocabulary. The A100 rerun instructions use Podman. The H100 launcher, Apptainer build recipe and submission commands have not been published.

Within each task, the recorded vLLM revision and measured source tree agree across clusters. Qwen used benchmark prompt seed `1795580955` on A100 and `1795604094` on H100. GPT used `1795559967` and `1795614421`, respectively. Qwen uses the same model snapshot at different TP settings. GPT uses two snapshots at the same TP. In the pinned Hugging Face manifests, all 15 indexed GPT weight shards have identical SHA-256 hashes. Only the model card and `generation_config.json` differ. The H100 revision omits token ID `200012` from the default end-of-sequence list. The pinned public serving helper passes `--ignore-eos` for these fixed-length timing workloads.
